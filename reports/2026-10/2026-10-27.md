### 1. Octen-WebGR: Scaling Generative Retrieval to 200 Million Web Pages

- **LLM Score**: 0

- **URL**: <http://arxiv.org/abs/2610.35256v1>
- **Submitted**: 2026-10-26 11:39:04
- **Topic Keywords**: retriever, dense retrieval, query, queries, click, retrieval, rank, search
- **Reason**: LLM scoring failed.

#### T.A.R.G.E.T. Summary (from Abstract)
- **Topic**: Generative Retrieval for Navigational Search (Octen‑WebGR)
- **Aim**: Enable efficient, generalisable retrieval of web pages for navigational queries by generating constrained semantic identifiers from a language model
- **Rationale**: Click‑table methods excel on seen queries but fail to generalise; dense retrievers rank poorly on navigational targets, especially for unfamiliar queries; generative retrieval can combine the strengths of both approaches
- **Ground**: Store representations of 201 million URLs inside the parameters of a 4‑billion‑parameter language model; for a query the model generates a two‑token semantic identifier that is constrained to a pre‑computed table of real URLs, effectively performing retrieval by generation
- **Experiment**: Evaluated on real navigational traffic collected one month after training; compared Octen‑WebGR to a dense retriever trained on the same click data, the same retriever with a click prior, and frontier large language models answering from memory; metrics included top‑1 accuracy on unseen queries, performance on rarely visited pages, overall top‑1 accuracy, and resource usage; scaling experiments up to 32 M URLs showed sublinear growth of required model size and identified page exposure as the limiting factor
- **Takeaway**: Octen‑WebGR achieves 59.6 % top‑1 accuracy versus 46.5 % for a click‑enhanced dense retriever and 37.5 % for frontier LLMs; the 4B model runs on a single GPU with 10 GB memory compared to 412 GB for exact dense retrieval; performance scales sublinearly with index size and is limited more by page exposure than model capacity; the models and code are publicly released

#### Abstract
> Navigational search aims to find a single target page among hundreds of millions of web pages. Click tables work well for queries seen before but cannot generalise to new formulations, while embedding retrievers generalise across content but often rank navigational targets poorly. We introduce Octen-WebGR, a generative retrieval framework that stores web pages in the parameters of a language model: given a query, the model generates a two-token semantic identifier constrained to a table of real URLs. We develop Octen-WebGR-4B, which indexes 201 million web pages, and evaluate it on real navigational traffic from the month after training. Generative retrieval is most effective on new ways of asking for familiar pages: for unseen queries targeting pages with substantial interaction history, it ranks the correct page first 30.9% of the time, against 17.2% for a dense retriever trained on the same clicks (21.4% with a click prior). Embedding retrieval keeps an advantage on rarely visited pages, so the two approaches generalise on complementary sides, the query and the page. Over all navigational traffic, Octen-WebGR reaches 59.6% top-1 accuracy, against 46.5% for a click-enhanced dense retriever and up to 37.5% for frontier LLMs answering from memory, which cost at least 40 times as much per query. The 4B model runs on a single GPU with 10 GB of memory, compared with 412 GB for exact dense retrieval. Scaling experiments with up to 32 million URLs show that, when every query-page pair is seen equally often, the model size needed grows sublinearly with index size, and that retrieval is constrained more by page exposure than by model capacity. We release Octen-WebGR-4B and Octen-WebGR-0.6B with their identifier tables and inference code.

#### T.A.R.G.E.T. Summary (from Full Text)
- **Topic**: Confidence‑Aware Reinforcement Learning for Retrieval‑Augmented Generation (CalibraRL)
- **Aim**: Align a model’s confidence with its factual correctness and dynamically adjust abstention incentives so that large‑language‑model QA systems answer only when reliable, reducing hallucinations while maintaining coverage.
- **Rationale**: Existing RL debiasing rewards correctness but ignores confidence, treats all IDK choices equally, and uses static incentives, causing over‑confidence and mis‑calibrated abstention. A reward that penalizes over‑confident mistakes and rewards IDK when evidence is weak can better match confidence to truth.
- **Ground**: LLM QA systems routinely hallucinate. Prior methods (TruthRL, R‑Tuning) lack a confidence signal, use uniform IDK rewards, and have static incentives. CalibraRL introduces a confidence proxy (mean token probability), a Brier‑based answer reward, and an adaptive abstention reward derived from a Beta posterior over query‑group accuracy. Policy optimization uses Group Relative Policy Optimization (GRPO) and requires only existing rollouts and correctness checks.
- **Experiment**: Models: LLaMA3‑8B‑Instruct and Qwen2.5‑7B‑Instruct. Training: SFT + CalibraRL vs baseline TruthRL. Datasets: NQ, TriviaQA, HotpotQA. Metrics: Precision, Truthfulness, Effective Reliability (ER), Expected Calibration Error (ECE). Results: CalibraRL consistently outperforms TruthRL on all datasets, with the largest ER gains on HotpotQA. Ablation shows that both λc>0 (Brier penalty) and λa>0 (adaptive abstention) are essential for best performance.
- **Takeaway**: By coupling confidence estimation with a calibrated reward and query‑level abstention, CalibraRL improves factual accuracy, reduces hallucinations, and yields better calibration without extra labeling effort, making it a practical enhancement for large‑scale retrieval‑augmented LLMs.

#### Abstract
> Large language models (LLMs) often produce plausible but incorrect answers, motivating reinforcement learning methods that reward correct answers, penalize incorrect answers, and allow abstention. However, fixed outcome-based rewards do not distinguish incorrect responses with different confidence levels or account for differences in answering reliability across queries. Consequently, such rewards may inadequately penalize overconfident errors and fail to discourage unnecessary abstention. We propose CalibraRL, a reinforcement learning framework that incorporates response confidence and query-level answering evidence into reward design. For non-abstaining responses, CalibraRL combines correctness-based utility with a Brier-based penalty that encourages agreement between confidence and correctness. For abstentions, it estimates conditional answering reliability using a Beta posterior derived from the correctness of non-abstaining responses within each sampled group. The abstention reward increases with the posterior probability that the model's accuracy on non-abstaining responses is below a predefined threshold. CalibraRL reuses training rollouts without requiring additional annotations indicating whether the model knows the answer to each question. Experiments on three QA datasets demonstrate that CalibraRL improves answer precision and reduces hallucinations compared with strong baselines. Further analysis shows that CalibraRL reduces mean expected calibration error (ECE) by 30.8\% across two backbone models and three datasets, highlighting its potential to improve the reliability of retrieval-augmented generation (RAG) in web search.

### 5. Read the Route: Attention-Steered Hypergraph Retrieval for Multi-hop RAG

- **LLM Score**: 0

- **Authors**: Jiate Liu, Liuyi Chen, Xiaofei Yuan, Yifu Tang, Zihan Yang, Xu Zhou, Zhengyi Yang
- **URL**: <http://arxiv.org/abs/2610.35412v1>
- **Submitted**: 2026-10-26 13:24:28
- **Topic Keywords**: query, relevance, rag, retrieval, rank
- **Reason**: LLM scoring failed.

#### Abstract
> Graph-based retrieval-augmented generation (GraphRAG) answers multi-hop questions by organizing a corpus into a graph and retrieving along its structure. Existing retrieval methods face two limitations. Diffusion- and similarity-based methods expand retrieval along fixed edge weights or by similarity to the question, without resolving its implicit entity references, allowing relevance errors to accumulate across hops. In contrast, exploration-based methods let an LLM reason about the next hop, but require a separate generation at each hop, leading to high inference costs. We observe that an LLM can resolve implicit entity references from retrieved passages and a multi-hop question before generating any tokens. Further analysis identifies a small set of attention heads, termed addressing heads, that capture this capability across multiple hops in a single forward pass. Building on this finding, we propose HyperAddress, which runs Personalized PageRank on a description-labelled hypergraph, using addressing heads to determine the restart distribution and transition weights, thereby guiding multi-hop retrieval without any generation at query time. On MuSiQue, 2WikiMultiHopQA, and HotpotQA, HyperAddress outperforms the strongest baseline by 3.5 points of Recall@5 and 7.4 points of All@5 on average, with gains that grow with the number of hops. It answers more than twice as fast and builds its index at half the cost.
